## 一页速览（分享前看这个）

**要回答的问题**：对话无限增长、模型上下文窗口有限——各家 agent 怎么"压缩"？

**一句话答案**：压缩 = 让模型把旧对话重写成一份"工作总结"，用摘要顶替旧消息，只把最近的部分原样留给模型看。

**三个必须提前统一的概念**（第零图）：
1. 消息有三种角色：user / assistant / toolResult
2. 一轮（turn）以 user 消息开启；assistant(toolCall) 和 toolResult **永远配对**，拆开 = 孤儿 tool（真实踩过 DeepSeek 400）
3. 磁盘存的 ≠ 模型看到的：磁盘全量只追加，模型看到的 = buildContext 回溯"当前叶子路径"

**三家的核心差异一句话**：
| | 存储 | 压缩= | 切点约束 |
|---|---|---|---|
| 我们 | JSONL 树（可回退） | 追加 compaction entry | 保留区第一条 ≠ toolResult |
| pi | append-only 日志 | 追加 compaction entry | 回退到轮起点（turn 边界） |
| DSH | 日志 + surface 视图 | surface replace | tool-pairing 配对平衡 |

**分享主线逻辑**：会话机制（第零图）→ 三家存储模型为何不同（图一）→ 同一段对话三家切点在哪、为什么（图二，核心）→ 压缩后模型看到什么（图三）。
