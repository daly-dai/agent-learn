# 核心功能缺口补充 —— 对照成熟 Agent 方案（2026-08-31）

> **定位**：PLAN.md 7.3 的**补充材料**。对照成熟 agent（Claude Code / pi / DSH / Codex / Cline / Aider / OpenHands）整理出**PLAN 里没有、但被业界公认为核心**的功能缺口，供判定排期。
> **判定流程**：按 AGENTS.md 11.5——本文档是"判定材料"（谁有这个 / 我们的风险 / 为什么核心），用户判定「核心 or 完善」后，才按流程写入 PLAN 7.3 排期表。**本文档不直接改 PLAN。**
> **筛选原则**：只收"成熟 agent 普遍都有、且缺了会在真实使用中踩坑"的项。PLAN 已有的不重复（如 subagent=C3、hooks=B5、diff 预览=B4、记忆分层=B6）；教学上刻意不抄的也不收（见文末"不建议抄的"）。
> **事实核查**：以下每项"我们现状"均已实读代码核实（grep 证实：`deepseekModel.ts` 无 retry、无会话级锁、`prompt.ts` 硬编码不读文件、工具层无系统化 schema 校验、无后台任务能力）。

## S 级：不做会在真实使用中踩坑

### S1. 模型请求重试与退避 → 建议编 B9

- **谁有这个**：Claude Code（429/5xx 自动指数退避）、pi（pi-ai 请求层重试）、DSH（llm 包重试策略）。这是所有生产 agent 的标配。
- **我们现状（风险）**：`lib/deepseekModel.ts` 的 `postChatCompletion` 把任何错误（网络抖动、429 限流、5xx）一次性转成 `stopReason:"error"` 的受控消息，**run 直接终局**。用户眼里：agent 说话说一半就"网络请求失败"，一切重来。DeepSeek 高峰期限流并不罕见。
- **做什么**：`postChatCompletion` 里加重试层——**瞬时错误**（429/5xx/超时）指数退避重试 2~3 次（如 1s/2s/4s，`Retry-After` 头优先）；**永久错误**（401/400）不重试直接 fail-fast；重试过程发轨迹事件（O 层原则：引擎外可观测）。请求加空闲超时兜底（防挂死）。
- **长在哪**：`lib/deepseekModel.ts`（适配层内部，引擎无感——正好验证"provider 差异关在适配层"的分界力）。
- **验收**：用 stub fetch 模拟前两次 429 第三次成功 → complete 正常返回且轨迹有 2 条 retry 事件；401 → 不重试。
- **教学点**：瞬时错误 vs 永久错误的分类学；重试是适配层职责（为什么不放引擎里）。

### S2. 工作区记忆文件注入（AGENTS.md / CLAUDE.md 机制）→ 建议编 B10

- **谁有这个**：Claude Code（CLAUDE.md）、pi（`.pi/` + AGENTS.md）、Codex（AGENTS.md）、Cursor（.cursorrules）、DSH（settings + 项目上下文）——**全部主流编码 agent 的第一公民功能**。
- **我们现状（风险）**：`_pipeline/prompt.ts` 是硬编码常量。agent 每个会话都"失忆"：不知道工作区的规矩、命名约定、"测试怎么跑"。用户每次都要在对话里重新交代。PLAN 的 C8 Skills 是"按需调用的指令包"，**不是**"每次都注入的项目记忆"——两者互补，C8 替代不了它。
- **做什么**：`systemPrompt` 常量改成 `createSystemPrompt(workspaceRoot)` 工厂——尾部拼接 `workspace/AGENTS.md`（存在才注入；加简单缓存防每请求重读；文件里可再支持 `@文件` 引用行，一期可不做）。配套写一份 `workspace/AGENTS.md` 种子文件做教学示例。
- **长在哪**：`_pipeline/prompt.ts`（E2 重构后正好留了这个扩展位，头注释写着"将来 C8 Skills 注入也在这里扩展"——记忆文件先来，同一落点）。
- **验收**：workspace/AGENTS.md 写一条规矩（如"回答用表格"），新会话模型遵守；文件不存在时行为与现在完全一致。
- **教学点**：模型上下文的三个来源（系统提示词 / 项目记忆文件 / 会话内消息）与各自的生命周期；为什么记忆文件注入属于产品层而不是引擎。

### S3. 会话级运行锁 → 建议编 B11

- **谁有这个**：所有成熟 harness 的隐含前提（pi session 单写者、Claude Code 一会话一进程、DSH 会话互斥）。
- **我们现状（风险）**：`runControllers` 按 runId 记（`lib/runControl.ts`），**同 sessionId 没有互斥**。两个标签页（或刷新后旧流未断）对同一会话并发 POST → 两个 run 交错 append 同一个 JSONL → parentId 树分叉错乱、leafId 漂移、压缩条目插在半路。这是数据损坏级 bug，只是还没人踩过。
- **做什么**：route.ts POST 入口加 per-session 占用表（`Map<sessionId, runId>`，已在内存态 Map 体系内，与 E6 同源）；占用中返回 409 + 明确错误文案；finally 释放。与体检报告的前端竞态修复（SSE abort）互补——服务端是最后防线。
- **长在哪**：`lib/runControl.ts`（同一文件，概念同族：run 级取消 → 加会话级互斥）。
- **验收**：单测模拟并发两请求同 session → 第二个 409；不同 session 不受影响。
- **教学点**：JSONL append-only 的正确性前提是"单写者"——分布式系统里的锁，在单进程里的最小形态。

### S4. 中断 / 崩溃会话自愈（孤儿 toolCall 修复）→ 建议编 B12

- **谁有这个**：Claude Code（`[Request interrupted by user]` 合成结果）、pi resume（会话恢复时修复截断的对话）、Codex（同理）。
- **我们现状（风险）**：run 中途被 stop / 标签页关闭 / 进程崩溃时，JSONL 可能留下**有 toolCall 无 toolResult 的 assistant 消息**（`agent.ts:226-233` 提前 return 时未配对的工具、或落盘后进程死掉）。恢复会话再发消息 → `buildContext` 原样回放 → DeepSeek 400（`store.ts:211-218` 注释里那个"孤儿 tool"教训的同族问题，只是这次发生在**恢复路径**而不是压缩路径）。
- **做什么**：`buildContext`（或 loadOrCreate 后）扫描尾部：发现未配对 toolCall → **不改文件**，重建上下文时补一条合成 toolResult（`"（上次运行被中断，工具未执行）"`，isError=true）——pi 同款思路：存储是事实，修复发生在重建视图时。
- **长在哪**：`lib/session/store.ts`（buildContext 或其私有辅助函数，纯逻辑可单测）。
- **验收**：手工构造含孤儿 toolCall 的会话文件 → GET 后正常发消息不 400；合成结果进上下文且前端可见。
- **教学点**：会话文件承载不变量（toolCall/toolResult 配对）；"落盘事实"与"重建视图"分离，自愈只动视图。

## A 级：显著提升体验与安全，建议排期

### A1. 文件检查点 / 回滚 → 建议编 A6（依赖 B5 hooks）

- **谁有这个**：Claude Code（/rewind + checkpoints）、Cline（shadow git 快照）、Aider（每轮 auto-commit）。
- **现状**：写/改/删有**事前审批**（弹框），但**没有事后撤销**——模型改坏了文件，用户得自己开编辑器还原。
- **做什么**：写/改/删工具执行前把目标文件快照进 `.checkpoints/`（按 runId 分目录）；UI 提供回滚入口（最小版：会话面板"还原本次 run 的文件改动"）。
- **长在哪**：B5 hooks 注册表（onBeforeTool 正好是快照载体）→ 所以排 B5 之后。`.checkpoints/` 进 .gitignore。
- **验收**：让 agent 改一个文件 → 回滚 → 文件回到改前内容；审批被拒的操作不留快照。
- **教学点**：审批是事前闸门、检查点是事后安全网——两道防线的互补；为什么回滚粒度是 run 而不是单工具。

### A2. 运行中插话 / 消息排队（steering）→ 建议编 A7

- **谁有这个**：Claude Code 的核心体验（run 进行中打字 → 排队/打断当前 turn）；DSH 消息队列。
- **现状**：run 进行中用户要么干等、要么全弃（stop）。没有"补一句话修正方向"的中间态。
- **做什么**：最小版**排队**——run 进行中发的消息进队列（服务端接口 + `user_queued` SSE 帧），引擎在下一 turn 开始前注入 context；打断（把当前 assistant 收尾）做二期。和 S3 会话锁天然配套：锁保证"一次一个 run"，排队解决"锁住了我说不了话"。
- **长在哪**：route 新接口（仿 ask-user 的挂起-应答模式）+ `_pipeline/index.ts` 在 loop 前查队列 + UI 输入框不再禁用。
- **验收**：run 进行中发"顺便加上 X" → 当前 run 不中断，下一轮模型能看到并执行。
- **教学点**：agent 交互模型从"回合制"到"流式协作"；队列注入点为什么在 turn 边界而不是任意时刻。

### A3. 工具参数 schema 校验 → 建议编 B13

- **谁有这个**：pi（zod schema 驱动工具）、DSH（JSON Schema）、Claude Code（同）——参数校验是工具协议层的标准件。
- **现状**：参数检查散在各工具里手搓（todo 的 `validateTodos` 是唯一成型的），其余工具参数错 → 内部 throw → 模型拿到一条任意格式的模糊错误，难自纠。
- **做什么**：`RegisteredTool` 增加参数 schema 声明（用现成 ToolDefinition.parameters，即模型看到的说明书——**让说明书本身成为校验器**，一份数据两用）；`ToolRegistry.execute` 入口统一校验，失败返回结构化错误（"参数 path 应为 string，收到 number"）给模型。
- **长在哪**：`lib/tools/types.ts` + `lib/tools/index.ts`（注册表层，各工具不用改内部逻辑）。
- **验收**：故意传错类型 → 模型收到结构化参数错误并自纠重试成功；现有工具测试全绿。
- **教学点**：把"参数契约"从人肉约定变成机器可执行；工具报错也是给模型的反馈信号（错误信息质量 = 循环自愈能力）。

### A4. 后台任务（run_in_background）→ 建议编 C15

- **谁有这个**：Claude Code（run_in_background 三件套：后台运行 + 查询输出 + 终止）、DSH background tasks。
- **现状**：bash 阻塞整个 loop——让 agent 起个 dev server 或跑长测试，agent 就卡死在那，只能靠用户 stop。
- **做什么**：bash 工具加 `background: true` 参数 → 立即返回 shellId；新增 `task_output` / `kill_task` 工具（Claude Code/DSH 同款三件套）；输出落盘可滚动查询。
- **长在哪**：`lib/tools/bash/` 旁新增 BackgroundRunner（与 BashRunner 平级，PLAN C2 沙箱容器的"新 Runner 平级"模式先例）。
- **验收**：agent 后台起 `pnpm dev` → 继续对话 → `task_output` 查到端口输出 → `kill_task` 结束。
- **教学点**：同步工具 vs 异步任务的本质差异；完成通知如何进事件流（轮询 vs 推送）。

## B 级：小件，顺手做

### B1. 上下文余量指示
数据已齐（`stats.tokens` 在 done 帧里、压缩阈值在 config），只差 UI 读数盘加一格"上下文 X%"（对照 Claude Code 的 /context）。压缩是自动的但用户应该看得见"还剩多少"。改动量：一个组件格子。

### B2. 自动会话命名
首轮 assistant 回复完成后，用首条用户消息（或小模型一句话）生成 title 更新会话（title 字段和改名接口都有）。对照 Claude Code 自动命名。半小时小件。

### B3. 录制回放回归测试（golden trace）
PLAN 7.1 V 行自己承认"无 benchmark"但没排期。最小可行版：把真实 DeepSeek 的 SSE 流录成 fixture 文件，`deepseekModel` 的 SSE 解析/流式累积/`toOpenAiMessages` 用 fixture 回放做回归——**同时补掉体检报告指出的 deepseekModel 零测试缺口**，一举两得。教学点：依赖外部服务的层怎么测（录制回放 = 把不确定性钉死成确定性）。

## 不建议现在抄的（判定记录，防以后重复讨论）

| 项 | 谁有 | 为什么不抄 |
|---|---|---|
| 并行工具调用 | Claude Code / DSH | systemPrompt 明确"一次只调一个工具"是教学选择；DeepSeek 并发多 toolCall 场景少；引入并发会让 loop 执行语义复杂一档 |
| Plan mode | Claude Code | 审批分级（B1）+ 只读放行已覆盖大部分场景；等 steering（A2）和检查点（A1）落地后再评估 |
| 多模型路由/故障降级 | OpenHands 等 | 与"先跑通一家"原则冲突（PLAN 五）；S1 重试已解决 80% 的可用性问题 |
| 图像输入（用户上传图片） | Claude Code / DSH read_image | 协议、UI、模型适配三处改造，教学收益低；C12 的 read_image 已覆盖"agent 读图" |
| 文件外部改动监听 | Cursor 等 | 小众；单机单人教学场景价值低 |
| Prompt injection 防御机制 | 前沿话题 | 机制本身（内容隔离标记/双轨 LLM）对单模型场景效果有限——**但值得先作为知识点讨论**（"工具结果是不可信输入"），工程化等真实需求出现 |
