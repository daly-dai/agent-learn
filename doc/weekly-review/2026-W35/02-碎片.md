### pi（packages/agent/src/harness/compaction/compaction.ts，848 行）
- **保留尾巴**：CompactionSettings { reserveTokens: 16384, keepRecentTokens: 20000 }——压缩后保留最近 ~20k tokens 原文，不全压
- **切点在 turn 边界**：findValidCutPoints/findTurnStartIndex/findCutPoint——不切在消息中间
- **split-turn 处理**：切点若劈开一个 turn（用户消息在中间），前半段单独摘要成 "Turn Context (split turn)" 拼进 summary
- **文件操作追踪**：摘要里格式化 readFiles/modifiedFiles，作为 CompactionDetails 存进 compaction entry；下次压缩 extractFileOperations 把 prevCompaction.details 并进来（历史跨压缩累计）
- **摘要请求独立**：completeSimpleWithRetries 用 cacheRetention: "none" + 独立 sessionId（摘要不污染缓存，缓存不可复用）
- **previousSummary 递归**：generateSummaryWithUsage 传 previousSummary，新摘要基于旧摘要（摘要的摘要）
- **分支摘要**（branch-summarization.ts）：会话树支持 fork/回溯——从旧叶子导航走时，收集"共同祖先→旧叶子"条目做摘要成 branch_summary entry，回溯时不重读原文

### DSH（docs/subsystems/compaction.zh.md，官方文档）
- **能力 seam 三件套**：Service Definition（ctx.compaction 抽象）+ Provider（dsh-compaction-basic 后端）+ Consumer（dsh-command-compact 命令）；压缩是可选能力，不属于 agent loop 主干
- **两个自动触发**：CompactionTrigger = pressure（压力）| context-overflow（溢出）；API：compactIfNeeded / compactNow / compactRegion（区域）
- **锁事件**：compaction/start → summary → end 三个会话事件括住整个操作；崩溃 = 遗留锁可检测（有 start 无 end），不虚假声称完成
- **surface 变更唯一路径**：摘要不扩展 SurfaceEventType，作为 user/message 带 surfaceOp: { op: "replace", start, end } 替换
- **工具结果剪枝**（toolResultPruner）：确定性 head/middle/tail 剪枝超预算工具结果文本——**不生成摘要也能缩减**，无 LLM 成本
- **工具配对边界**：toolPairingBalancedBefore/After——区域边界保持工具调用/结果配对，不保持整个轮次（过大轮次中较早关闭的步骤可压缩）
- **错误分类**：ManualCompactionErrorCode = busy/cancelled/changed/summary/commit/persistence（changed = 选中范围已变）
- **压力压缩位置**：串行 agent/pre-step，先于请求推导；失败恢复走 agent/request-error

### 我们 B2 的实现细节（lib/session/store.ts prepareCompaction + _pipeline/compact.ts）
- **保留尾巴**：keepRecentMessages（config compactKeepRecent）——尾部原文保留，只压前面
- **增量更新（D3）**：previousSummary 递归——上一个压缩点之前的旧消息不再喂模型，信息由 previousSummary 代表；待压区 = 上次保留区第一条 → 现在
- **切点约束（API 驱动，2026-08-25 修）**：保留区第一条不能是 toolResult——ReAct 中 assistant(toolCall) 先、toolResult 后；切点落在 toolResult 上 → 配对的 toolCall 被压掉 → 孤儿 tool → DeepSeek API 400。修法：切点往前挪直到第一条不是 toolResult
- **经济性检查（Reasonix D6）**：tokensToSummarize < minCompactTokens 不压——省下的 token 不够抵消一次摘要调用成本
- **降级**：mockMode 拼贴；真实模型失败也拼贴（压缩是防爆窗，失败不能拖垮对话）

### 三方切点约束对照（同样的问题，三种驱动）
- 我们：保留区第一条 ≠ toolResult —— **API 契约**驱动（DeepSeek 400 教训）
- pi：切点落在 turn 边界（findTurnStartIndex）—— **结构完整**驱动（turn 是语义单元）
- DSH：工具调用/结果配对平衡（toolPairingBalancedBefore/After）—— **可重建**驱动（重放可恢复）
- **实现层默认值（config.ts）**：thresholdRatio 0.8（80% 窗口触发）/ retainRatio 0.16（保留 16% 尾巴，**比例制**，vs pi/codex 固定 20k）/ maxTokens 8192（摘要输出上限）/ compactionRetries 1 / maxOverflowRetries 1 / auto true
- **溢出绕过保留**：context-overflow 触发时 retainTokens=0（强制一次有效缩减，不按保留策略）
- **剪枝先行**：pressure 触发达标后先跑 toolResultPruner（model-free pass）落地 → 重测 → 仍超才选范围摘要
- **循环重试**：compactionRetries+1 轮，每轮重新 selectCompactableRange；全失败 throw "still above threshold"
- **摘要复用会话前缀**：ctx.llm.stream() 的 prefix 复用会话自己的 system prompt/tools/messages——**不失效 provider KV cache**（vs pi 隔离缓存 cacheRetention:none——两种缓存哲学相反）
- **摘要独立模型可选**：summarizationProvider/summarizationModel 可指定；modelPolicies 支持按 provider/model 精确覆盖阈值与保留
- **范围选择（region.ts selectCompactableRange）**：从尾巴向前累计 token 到 retainTokens 预算 → 向前挪到 toolPairingBalancedBefore 满足（配对平衡）→ { start: 首节点, end: 切点前一个 }

### codex（子代理精读，core/src/tasks/compact.rs + session/turn.rs + state/auto_compact_window.rs）
- **三套并存压缩**（tasks/compact.rs:28-85 分发）：① 本地 LLM 摘要（memento）② 远程 /v1/responses/compact（服务端摘要）③ **TokenBudget**：完全无摘要，直接 start_new_context_window 只留结构化 world state——**新方向：放弃摘要**
- **自动压缩时机**：PreTurn（采样前：token_limit_reached / 换模型 comp_hash / 模型降档）+ MidTurn（采样后：should_roll_over = 模型 new_context_window 工具请求 || token_limit_reached）
- **token_limit_reached 判定**：scope_tokens >= (scope_limit + fallback_buffer)；BodyAfterPrefix 范围用 AutoCompactWindow 的 prefill 基线算窗口内增量
- **保留策略**：最近 20k tokens 的**真实用户消息**（旧摘要被过滤、assistant/tool 全丢）+ 新摘要（SUMMARY_PREFIX 包装成 user 消息放最后）——**与 pi 不同：保"用户消息尾"而非原始 tail**
- **摘要身份**：带"另一 LLM 交接笔记"身份且不叠加（不是摘要的摘要）
- **边界概念**：窗口 id 链（auto_compact_window）而非 turn 边界切点
- **纠正**：AutoCompactFallbackPrompt 是基础 limit 耗尽但 buffer 未满时注入的 developer 收尾提醒，不是摘要 prompt
- **guardian/mod.rs 的"重建压缩转录"是审批审查专用**（保留全部 user ≤10k + 首尾锚点 + 最近工具证据 ≤10k 40条，丢弃 developer/reasoning/图像）——不是会话压缩
- **协议层可见**：app-server/tests/suite/v2/compaction.rs:211-237 断言压缩请求 x-codex-turn-metadata（trigger=auto / reason=context_limit / implementation=responses_compact / phase=pre_turn / strategy=memento）
- **未决设计**：turn.rs:165-168 TODO——pre-turn 判定基于"上一轮结束时 token 状态"，未预判即将注入的 context diff + 用户输入（vs pi 的切点预算思路）
