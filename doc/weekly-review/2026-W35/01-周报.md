## 一、引擎纯净性：污染从哪来，偏函数怎么一劳永逸

**问题机制（为什么会被污染）**：工具注册时上下文不够支持 todo / askUser。工具（lib/tools/ 的 execute 函数）需要两个引擎级能力——todo 事件（任务面板）和 askUser（提问卡）——但工具定义时，引擎循环（lib/agent.ts）还没有 store / send 这些运行时能力。能力缺口 → 两条歪路：把业务逻辑塞进引擎（引擎知道 todo/askUser 怎么处理 = 污染），或工具里全局找状态（隐式依赖）。

**解法（偏函数 / 工厂闭包，借鉴 pi）**：`createToolRegistry(params)` / `createPipelineTools({ workspaceRoot, store, recorder, send })`——工具工厂收 params，**hooks（onTodoWrite / onAskUser）在工厂内部绑定**（闭包捕获），引擎循环只收"已经绑定了能力的函数"，零业务。

**为什么是核心**：这是依赖注入的第一课——"引擎的能力从哪来"只有一个干净的答案：**创建时注入，运行时只调用**。偏函数是 DI 的最简形态：比 DI 容器（cordis，本周五知识⑤）轻一个量级，比全局状态干净一个量级。E2 重构里同样手法：createPipelineTools 内部绑 askUserAnswer（拿 recorder.runId），route 壳不碰。

## 二、审批：一个情况迷宫的完整设计

**逻辑分支（情况多在哪）**：一个工具调用，可能 ① 只读放行（bash 窄表）② 按模式三档决定 ③ 危险参数拦截 ④ 请求用户确认（带超时）⑤ 拒绝并改写 ⑥ 记审批日志（decided 带 outcome）⑦ 前端三档切换 + 记忆。每个分支还有子情况。

**借鉴与优化（来源链）**：
- **只读放行**：抄 Reasonix shellsafe——单命令窄表（readOnlyCommands：cat/head/ls/grep/…+ pwsh 观察性 cmdlet）+ **参数级拦截**（nestedReadOnlyArgsSafe：find -exec / sort -o / git diff --output / sed -i——"子命令表只读，但参数能走私写操作"）。我们 JS 无 Go 的完整 AST 解析器，用词法近似，诚实交代取舍
- **三档模式不是自创**：pi ask/always/never 与我们一一对应；运行时切换入口 pi/codex/DSH/CodeWhale/Reasonix 全是标配（/settings、/permission、Shift+Tab）
- **fail-closed 底线**：宁可多弹框，不可漏放行。对照 Reasonix 参数级检查逐条核对暴露 4 处"参数走私写"缺陷（测试没兜住）
- **决策/副作用分离**：approval.ts 纯函数（ToolDecision = allow/block/rewrite 三态 + request）+ 15 单测；send/日志/超时留壳

**为什么是核心**：状态多、分支多的功能最容易烂成一坨 if。它的解法是**把决策层做成纯函数**（可测、可穷举），副作用层留壳——"决策与执行分离"是复杂功能的通用骨架。

## 三、压缩：我们实现了一种，各家方案各不相同

**我们实现的（B2，lib/session/store.ts + _pipeline/compact.ts）**：
- 三步压缩：prepareCompaction（切点/收集，纯计算）→ generateSummary（LLM 结构化摘要，失败降级拼贴）→ commitCompaction（落盘）
- compactionSummary 独立消息类型（普通消息渲染多轮后异常）
- **保留尾巴**：keepRecentMessages 尾部原文保留，只压前面
- **增量更新（D3）**：previousSummary 递归，上一压缩点前不重喂模型
- **切点约束（API 驱动）**：保留区第一条 ≠ toolResult（孤儿 tool → DeepSeek 400，2026-08-25 修）
- **经济性检查**（Reasonix D6）：压的区域太小不压（省下的不够抵消一次摘要调用）
- 自动（run 结束阈值/env）+ 手动 /compact 同源

**pi（compaction.ts 848 行 + branch-summarization.ts）**：
- 保留尾巴：CompactionSettings { reserveTokens: 16384, keepRecentTokens: 20000 }
- **切点在 turn 边界**（findTurnStartIndex）——不切在消息中间；**split-turn 处理**：切点劈开一个 turn 时前半段单独摘要成 "Turn Context (split turn)"
- **文件操作追踪**：摘要里格式化 readFiles/modifiedFiles，存进 compaction entry，下次压缩跨压缩累计
- **分支摘要**：会话树 fork/回溯时，"共同祖先→旧叶子"条目摘要成 branch_summary entry，回溯不重读原文
- 摘要请求独立：cacheRetention: "none" + 独立 sessionId（不污染缓存）

**DSH（compaction-basic 实现，src/config.ts + index.ts + region.ts）**：
- 能力 seam：Service Definition（ctx.compaction 抽象）+ Provider（compaction-basic）+ Consumer；压缩不在 agent loop 主干
- **双触发 + 重试**：pressure（0.8 阈值，agent/pre-step）+ context-overflow（request-error + retry 机制）；溢出绕过保留策略强制缩减
- **保留尾巴比例制**：retainRatio 0.16（16% 窗口）——vs pi/codex 固定 20k token，度量方式不同
- **切点 = 工具配对平衡**：从尾巴累计 token 到保留预算 → 向前挪到 toolPairingBalancedBefore 满足
- **剪枝先行**：pressure 达标准先跑 toolResultPruner（零 LLM 成本缩减）→ 重测 → 仍超才摘要
- **摘要复用会话前缀**（不失效 provider KV cache）——vs pi 隔离缓存（cacheRetention:none），两种缓存哲学相反
- 锁事件（start→summary→end）崩溃可检测；错误分类六类；摘要独立模型可选

**codex（tasks/compact.rs + session/turn.rs + auto_compact_window）**：
- **三套并存**：本地 LLM 摘要（memento）/ 远程 /v1/responses/compact（服务端摘要）/ **TokenBudget（放弃摘要，直接 start_new_context_window 只留结构化 world state）**
- 自动时机：PreTurn（采样前 token_limit_reached / 换模型 / 模型降档）+ MidTurn（采样后 should_roll_over）
- **保留策略**：最近 20k tokens 的**真实用户消息**（旧摘要过滤、assistant/tool 全丢）+ 新摘要（SUMMARY_PREFIX 包装成 user 消息放最后）——保"用户消息尾"而非 pi 的原始 tail
- 边界 = 窗口 id 链；摘要 = "另一 LLM 交接笔记"身份、不递归叠加

**Claude Code（知识点-05，官方文档 + 源码分析 + 知乎六大拆解）**：
- **触发**：不是撞墙才压——预留 20k 给摘要输出 + 13k 提前缓冲 + 连续失败 3 次熔断（省死锁调用）；1M 模型默认 ~967K 触发；/autocompact 可配
- **保留 = 脱水 + 九章节摘要 + 状态重建**：本地"脱水"（图片→占位）→ LLM 重写九章节结构化摘要（用户意图/请求/概念/文件/错误/过程/消息/待办/下一步）→ **状态重注入**（system prompt/CLAUDE.md/auto memory 从磁盘重载 + 重读最近 5 文件 + skill 重注入）——用户消息不原样保留
- **五段成本递增流水线**：Budget Reduction→Snip→Microcompact→Context Collapse 全本地零 API，LLM 摘要只是最后兜底——**零成本优先于摘要**（与 DSH toolResultPruner 同哲学，但做成完整流水线）
- **prompt cache 前缀稳定性是一等公民**：摘要在 fork agent 里做 + 共享缓存，刻意保持前缀稳定（服务端 cache_edits/context_management beta）
- **context rot 概念**：1M 时代官方反而建议主动 /compact（自动压缩发生在模型最笨的时刻）



**为什么是核心**：压缩是长上下文 agent 的命门，实现方案是设计空间的分水岭——触发（阈值 vs 压力+溢出 vs 预采样）、摘要（LLM vs 剪枝零成本）、保留（尾巴 vs 全量 vs 区域）、切点（turn 边界 vs 工具配对 vs API 契约）各家不同。只懂自己的方案 = 只知道一个点。
