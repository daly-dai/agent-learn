## 一、C8 Skills —— 三层信息 + 两条加载路径（本周主线，也是"糊里糊涂"的那块）

**它到底是什么**：一个技能 = **一个目录** + 一份 `SKILL.md`（可带 `scripts/` `references/` `assets/`）。

**机制：信息分三层，按需逐层展开**

| 层 | 是什么 | 什么时候进上下文 | 贵不贵 |
|---|---|---|---|
| 1 目录 | `name` + `description` | **每个请求都进系统提示词** | 便宜（每条约 200 字符，所以能常驻） |
| 2 正文 | `SKILL.md` 全文 | **被激活时**才进 | 贵（一份可以几千 token） |
| 3 资源 | `scripts/` `references/` … | 正文**引用到**才去读 | 可能巨大 |

⭐ **为什么这样分**：这是**上下文经济学**。三层分开 ⇒ **只有真用到时才付钱**。把三层压成一层（"把所有技能正文都塞进提示词"）会立刻撞墙 —— 这正是 C37 那个"可见技能上百怎么办"的病根。

**机制：同一份正文，两条激活路径**（共用 `renderSkillContent`）

- **模型自己喊**：调 `skill` 工具 → 正文进 **toolResult**
- **宿主代劳（手势）**：用户打 `/名字` → 宿主**注入一条 user 消息**（带 `source.kind = "skill-invocation"` 标记）→ ⭐ **这一轮模型零工具调用**

⭐ **为什么两条都要**：手势那条的判据是「**这一轮没有 `skill` 工具调用**」—— 它把"**用户明确要**"和"**模型自己判断**"分开了。用户打了 `/code-review` 还要赌模型会不会去读，是没道理的；而且模型判断失误时，用户没有任何补救手段。

**四条定了就省事的细节**：
- **身份 = 目录名**（frontmatter 里的 `name` 只是数据；不一致时按目录名加载 + 给一条诊断）
- **frontmatter 只认 3 个键**：`name` / `description` / `disable-model-invocation`
- **`disable-model-invocation` = 只退出第 1 层**：模型清单里没有它，但**面板里还在、`/名字` 还打得进**
- **清单是"每请求现拼的参数"，不落盘**（Q1 的答案：不做成一条会话消息）

**本周修的两个洞（都在这条链上，都是 C8 自己造出来的）**：
- **a1**：`parseFrontmatter` 把**正文里的分隔线**当成 frontmatter 收尾 ⇒ **静默吞掉前半段正文**（照常加载、零诊断）。判据定成 —— **真 YAML 解析器会报错的行我们也不收，它会接受的行我们照收**（别家全用真解析器 ⇒ 比 YAML 更严 = 拒掉别人能用的技能 = 自己造假阳性）。
- **a2**：未知命令文案漏了「**或技能**」（技能也注册进了同一份命令名单）。

> 共同点：**两个都是"失败路径只处理了一半"** —— 这是本周最该记住的一句。

## 二、A5 联网工具 —— 「搜索」和「抓取」是两件事

**核心结论**：`web_search` = **集成现成 API**（DeepSeek 服务端搜索，复用现有 key）；`web_fetch` = **自研**。

**机制与为什么**：
- **搜索是重资产**（索引 / 反爬 / 成本），**抓取是轻活**（一个 HTTP 客户端 + HTML→文本）⇒ 分开对待。
- ⭐ **没有任何一家 agent 自己建搜索引擎** —— 搜索一律是"调用别人现成的搜索能力"。
- 抓取自研的价值不是"省钱"，是**可控 + 可教学**：SSRF 闸门自己写（含经典绕过用例），HTML→文本用现成库（turndown/GFM）。

**借鉴**：Reasonix 的「**搜索与抓取分离**」哲学。⚠️ **pi 根本没有 `web_search`**（已核实）⇒ A5 的参考系只能是 DSH / smolagents / CodeWhale / codex / Reasonix。

## 三、A3 轨迹视图 —— 先能「定位」，再谈「看懂」

**机制**：轨迹是**一等公民**（调试黑匣子）。数据层 = 折叠（纯函数）+ **按会话归属**（文件名带会话前缀）+ **真·部分读**；A3 = 视图层（顶部 tab + 竖轴记录表）。

**⭐ 一个真问题：`readTraceMeta` 为什么要"只读首末行"**
「只读首末行」**不等于** `readFile` 之后 `split("\n")[0]` —— 那还是把 1MB 全读进来了。真做法：**首行读文件头 ~1KB**；**尾行 `fstat` 拿 size、再从末尾读一小段**。

**⭐ 判据**：**尾行是不是 `trace_end`，就是 run 完整性的判据**。服务崩掉的文件尾部没有 `trace_end` ⇒ 界面上**该标出来，而不是假装正常**。这是"知道它什么时候会失败"的一个具体样本。

**借鉴**：DSH `packages/client/ui-trajectory`。⚠️ **我上一轮漏找过它** —— 搜 "trace" 命中不了 "trajectory"，**正则没命中不等于不存在**。

**教学点（删掉的东西也一样值钱）**：删掉了 `TraceSnapshot` —— 事件协议里**早就有** `tool_execution_start.args` / `tool_execution_end.result` / `tool_permission.*` / `message.usage` / `compaction.*`，快照字段是**过度设计**（提前设计了、结果没人用）。

## 四、⭐ 提示词是缓存的前缀 —— 一个注释骗了我们三天

**机制**：系统提示词是每个请求的**前缀**；**KV 前缀缓存只在"前缀逐字不变"时命中**。

**踩的坑**：`prompt/index.ts` 文件头写着「每天变一次，**天粒度，影响很小**」，而代码用的是 `timeStyle: "short"` ⇒ **渲染到分钟**。实测 `18:43` 与 `18:44` 输出不同 ⇒ **提示词每分钟变一次 ⇒ KV 前缀缓存一次都命中不了**。

**为什么这条最值钱**：
1. **注释写的取舍前提，从一开始就是错的** —— 而我们（包括我）信了它三天。
2. 它还**连累过 C8 的一个论证**：选"清单每请求现拼进提示词"时写「这个代价我们已经在付」——**那句当时也是错的**。
3. 修法不是"删掉时间"，而是**降粒度**：`formatCurrentTime` → `formatCurrentDate`（去 `timeStyle`、留时区）。

**推广成一句话**：凡是"每请求拼进提示词"的东西，都要问一句 —— **它是天粒度，还是分钟粒度？**

## 六、⭐ 验收的粒度：「笼统说没问题」和「逐项有证据」不是一回事

**两条真实教训**：

1. **用户实测是唯一证据时，必须记清粒度。** C8 T8 的 ③④⑤⑥⑦ 是用户在浏览器里实测的，但反馈是**笼统的「没啥问题」、没有逐项留证** —— 而其中两条（**手势那一轮没有 `skill` 工具调用** / **打错的两种行为**）**没有任何单测兜底**。记档时写清"当时只到这个粒度"，否则将来回查会误以为有硬证据。
2. **一条"改前改后都绿"的测试，光"绿"证明不了它有保护作用** —— 唯一能把它和"摆设"区分开的动作是**变异检查**：把判据故意收紧 → 看是不是**正好**红在那一条（本周验过：收紧放行条件 ⇒ 正好那两条红、第三条照常绿）。

**为什么是核心**：AGENTS 第 0 条的判据是「**别人能跑通 + 知道它什么时候会失败**」。"知道它什么时候会失败"这句**只能靠这两条纪律兑现**：**证据分级** + **变异检查**。

## 七、判据升级：「作品才算学会」

**改了什么**：AGENTS 第 0 条的前提判据从「**学习优先于产出**」换成「**作品才算学会**」—— **目的没变**（还是学会 agent），**变的是"怎么才算学会"**：从"**我自己**能跑通"换成「**别人**能跑通 + **知道它什么时候会失败**」。

**为什么不是文字游戏**：它把"懂了吗"这个**无法检验**的问题，换成两个**能检查**的问题 —— ① 别人（不含你）能不能跑通？② 你能不能说出它**什么时候会坏**？这也解释了本周为什么花那么多力气在"**诚实记缺口**"上（a1 的残余边界 / a2 无测试 / 「诊断可见」只是**弱可见**）。

## 八、本周新增 / 加固的四条纪律

1. **push 与 commit 是两件事**（来自一次**真实的未授权 push**）：commit 是本地的、**可撤**；push 是发给外部的、**不可逆**（仓库是 public）。「改」≠「推」；**上一轮确认的 commit ≠ 这一轮的 push 授权**；**禁止为 push 升级沙箱权限** —— 沙箱拦住**正是该停下来问的信号**。
2. **章节编号只在 `PLAN.md` 内部用**，其它文件一律用「**文件 + 名字**」引用：编号会重排（09-15 就重排过一次、牵动 8 个文件），而**名字能被 grep** —— 名字改了你能搜到，编号改了它只是**静默指到别处**。
3. **实现与单测同目录、都叫 `index`**（升为硬规则），并给出一条**可查的不变量**：「**不叫 `index.test.ts` 的测试文件数应为 0**」（今天 55 个测试文件、违规 0）。**规则该有的形态：不靠记性，靠一个能查的数。**
4. **页面 / UI 生成必须先调 `frontend-design` skill**（硬规则，不设例外）。⚠️ 但「**加载 ≠ 遵守**」：A3 那次加载了 skill 却没读已确认的原型 ⇒ 三处提案被原型当场证伪、全部撤回（**T2 的 `grep` 返回 No matches、绿色、无报错，却是真正的根因**）。规则拦不住这个破绽，只能靠人抓。

## 附二、经验（**不是**知识 —— 熟能生巧那一类）

- **`Get-Content` 默认按 GBK 读** ⇒ 同一份 `PLAN.md` 报 **230 行**、真值 **307 行**（**77 个换行被静默吞掉**）。根因：本机 harness 跑的其实是 **Windows PowerShell 5.1**（`PSEdition=Desktop`）+ **ConstrainedLanguage**，DSH 的编码 preamble 每条命令都报 `CannotCreateTypeConstrainedLanguage` ⇒ pin 没生效。**要么用 harness 的 read/grep，要么 `-Encoding utf8`。**
- **中文经 PowerShell 管道必乱码**（解码按 GBK）⇒ 要拿 git 的中文输出，**让 `cmd` 做字节级重定向**，再用 read 工具读文件。
- **`[类型]::静态方法()` 在受限语言模式下被禁**（`"hello".Substring(0,2)` 合法）—— 实测纠正过我一个错判（我以为两个都禁）。
- **node 起不了子进程**（`spawnSync ... EPERM`）：与那 5 条既有测试失败**同源**，也让 node 写的文档比对脚本直接崩 ⇒ **沙箱内要比对文件，用纯 PowerShell**。
- **双引号嵌进双引号字符串**（`it("…"…"…")`）→ `tsc` 报 `TS1005: ',' expected`：**只有跑 tsc 才发现**（同一会话犯两次）。
- **探针本身可能是坏的**：`& pwsh -Command '"end"'` 让 pwsh 吃掉内层引号，校准用例本应 `exit=0` 却报 `1` ⇒ 那批数字**全是垃圾、当场作废**，改从 stdin 传脚本才拿到真规则。
- **commit 用错了消息文件**（把 `t8-3` 又提交了一次）⇒ 未 push 时 `--amend -F` 修掉，并核对 `--numstat` 确认"**只改了消息、文件内容没动**"。
