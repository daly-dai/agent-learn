## 八、复查报告（2026-09-21 开工）

> 形态按 5.0 定的：每条**结论 + 证据**（`file:line` / 真机样本 / `.traces/` 引用）。

### ① 契约与语义 —— ✅ **一致，判"不改"**（理由可检验）

三处并排（这就是证据）：

| 处境 | 怎么处理 | 模型看到什么 |
|---|---|---|
| HTTP 非 2xx（403/404/429） | **算结果**（`ok:true` + `status`） | `Fetched <url> (HTTP 403)` + **错误页正文**（`fetcher/index.ts:143-152`） |
| 搜索无结果 | **算结果**（明说） | 「这次搜索没有返回任何来源。换个说法再搜，或如实告诉用户你没查到。」（`web-search/index.ts:269-273`） |
| 内容类型不支持（PDF / 图片） | **抛错** | `web_fetch 不支持这个内容类型：…`（`web-fetch/index.ts:90-96`） |
| 协议坏掉 / 被闸门拦 / 超时 / 字符集解不了 / 重定向超限 | **抛错**（`isError`） | 失败原因标签 + `detail` |

⇒ **边界是清楚的**：**"外部世界给的东西"永远是结果**（哪怕它是个错误页——"需要登录""慢一点"本身就是最有用的信息）；**抛错只给"我们要的东西拿不到 / 拿回来不能用"**。另一条不变量两侧都成立：**绝不给模型空字符串**（搜索那句明说、fetch 有状态码 + 正文）。

### ② 限额与截断（含 **C22**）—— ⚠️ **确认缺陷，判"修一半"**

**现状：三层上限被压成一个布尔。**

| 层 | 在哪 | 上限 |
|---|---|---|
| 抓取（字节） | `fetcher/index.ts:253-302` `readCapped` | `maxBytes` = 1 MiB（到顶 `reader.cancel()`，**剩下的字节永远拿不到**） |
| 转换（字符） | `convertHtml`（HTML→Markdown） | 自己的字符上限 |
| 呈现（字符） | `render/index.ts:78-104` | `maxOutputChars` = 200k |

三者在 `web-fetch/index.ts:108` 被 `||` 成一个 `bodyTruncated` ⇒ `details.truncated` **只有一个布尔**；模型看到的 footer 只有一句「内容已截断。要读全文，请抓一个更具体的 URL…」——**它不知道是哪一层截的、也不知道被截掉了多少**。搜索结果侧**同病**：`mergeSearchResults` 把"我们按上限砍的（`dropped`）"与"子查询自己带回来的 truncated" `||` 成一个布尔（`web-search/index.ts:247-248`）。

**判定**（按定稿写死的标准"截断必须能区分上游截的与我们截的"）：**做不到 ⇒ 判"修"**。但**按成本切成两半**：

- ✅ **做（低成本、纯信息增量）**：标志**分层**——`details.truncated` 改成具名分层（`{ fetch, convert, render }`），**并且模型可见的那句 footer 也要按层说清**（"响应超过 1 MiB，只取了前 1 MiB" / "正文超过 20 万字符"）。搜索侧同理（`dropped` vs 子结果 truncated 分开报）。⚠️ **两个面都要改**：`details` 是给前端/轨迹的，**模型那一侧才是它据此判断的地方**。
- ❌ **仍不做（C22 的后半）**：opencode 那条「**留一份 + 给路径**」（超限内容落盘、把路径给模型）——它是**增强不是缺陷**，要新增存储层与限额语义，且 C22 原文写着"**没有真机数据**"⇒ **记档 + 写明触发条件**：碰到"模型确实需要被截掉的那段"的真实案例时再开。
