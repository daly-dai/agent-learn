## 五、详细设计（2026-09-21 **范围定稿**）

### 5.0 定稿：9 条分三类，**出口 = 逐条给结论**

> 本项是**复查**不是加功能 ⇒ "做完"的形态不是"改了什么代码"，而是**9 条逐条有结论**：
> **修**（按 11.5 先红后绿 + 独立 commit）/ **不改**（写明理由）/ **开新项**（入池）。
> 分类只决定**深度**，不决定"做不做"——9 条全在范围内（用户原话"整体复查"）。

| 类 | 条目 | 深度要求 |
|---|---|---|
| **甲：有已知疑点，必须给结论** | ① 契约语义 · ② 限额与截断（含 **C22**）· ③ 内容与编码 · ④ 安全 · ⑤ 抽取质量（含 **C23**） | 每条要写到"**确认 or 否定 + 处置**"，并附证据（file:line / 真机样本 / 轨迹引用） |

| **丙：需要一手对照 / 真机** | ⑧ 对照复查（三家源码）· ⑨ 提示词效果 | 产物形态先定死（见 5.2），否则会变成"我觉得还行" |

### 5.1 逐条：怎么查 + **判定标准**（没有判定标准 = 复查会变成聊天）

| # | 怎么查（可执行） | 判定标准（什么算"有问题"） |
|---|---|---|
| ① | 把三处并排读：`fetcher` 的"非 2xx 算结果"（`fetcher/index.ts:143-152`）· `web-search` 的空结果明说（`NO_RESULTS`）· 引擎的 `isError`（只有抛错才置位） | 同一个事实（"没拿到东西"）在三处**不能有两种说法** |
| ② | 读 `config.web` 那 **8 个旋钮**的真值（`config/index.ts:185-204`）＋ `readCapped` 与 `render` 的**两次截断** | ⭐ **截断必须能区分"上游截的"与"我们截的"**（C22 第一条）；⭐ **生产者上限与模型上限要分两层**（C22 第二条）——现在都做不到就记"要修" |
| ③ | `parseCharset` 只看**响应头**、不嗅探 `<meta charset>`（`fetcher/index.ts:216-223`，与 DSH 一致） | 拿一个**真实 GBK 页面**喂进去：能读 ⇒ 边界无害；乱码 ⇒ 必须修（A5 真机已知会乱码，**大概率变"修"**） |
| ④ | 四块分开看：闸门覆盖面 · **重定向**（待拍板，见 5.3）· DNS rebinding TOCTOU（已记档）· 注入只有标注 | 每块要么**确认现状可接受并写明依据**，要么给出修法；不许含糊 |
| ⑤ | C23 的降噪：**有 2026-09-14 的真实样本**（36氪频道矩阵 17 个品牌名，粗估 2000 字符 ≈ 40%） | 用真样本量一次：噪音占比可忽略 ⇒ 不改（记档）；不可忽略 ⇒ 修（先确认容器，不按标签删导航） |
| ⑥ | 失败时**轨迹里能不能看出错在哪一步**；另：**重定向链是否可见** | 2026-09-21 已核出一条：最终地址**是**给模型的（`render/index.ts:11,83` 的 `Fetched <最终地址>`），但**中间跳转链哪儿都没有**（`details` 里也没有）⇒ 出事时回答不了"它从哪跳过来的" |
| ⑦ | 数一次搜索要花几次模型调用：`maxQueries=4` ⇒ 一次工具调用最多 4 次；`maxUses=5` | 去轨迹里找"模型乱给 4 条 query"的实例；有 ⇒ 考虑提示词约束或调小上限 |
| ⑧ | DSH `packages/web/tool-web/` · opencode **两套并存**（`packages/core/src/tool/` + `packages/opencode/src/tool/`，导航卡已订正）· codex `web.run` | 逐项再对一遍；**只记"差距"与"我们是否要做"**，不照抄 |
| ⑨ | **判据形态 = 取 3~5 次真机（轨迹里）**逐条判：该不该查 / 引用是否规范 | 定在 5.2；**没有轨迹样本就不给结论**（不许写"感觉还行"） |

### 5.2 丙类的产物形态（先把话说死，免得复查变成"聊天"）

- **⑧ 对照复查**：一张表——`项 / DSH 怎么做（file:line）/ opencode 怎么做（file:line）/ codex 怎么做 / 我们的选择 + 理由`。**只列有差距的项**，一致的项不写。
- **⑨ 提示词效果**：从 `.traces/` 里取**最近 3~5 次**含 `web_search` / `web_fetch` 的 run，逐条判两问：① 这次**该不该查**（决策边界那条 10% 阈值）② 引用是否写成 Markdown 链接。判完给"改提示词 / 不改"。

### 5.3 重定向策略（✅ 2026-09-21 用户拍板：**保留我方现状 + 记跳转链**）

**两条路线**：DSH 路线（**同源跟随 ≤5 + 跨源拒绝**，让模型重新发一次工具调用）vs 我方现状（**任意来源都跟，但每一跳都过地址闸门**）。

**拍板结果：保留我方现状**，依据两句可检验的话：① **闸门在地址层** ⇒ "跳数"不是信任边界；② **最终地址对模型可见**（`render/index.ts:11,83` 的 `Fetched <最终地址>`）。改 DSH 属**返工**（fetcher + 用例）且真实网页跳 CDN 常见、手感变差。

⚠️ 但我方路线**唯一真实短板是"静默"**（跨源跳转不产生第二次工具调用 ⇒ 轨迹里看不见），所以**顺带补一个低成本补丁（用户同时拍下）**：

> **把跳转链记进 `details`**（一个数组，形如 `["https://a", "https://b", "https://c"]`）。
> 只记**发生了什么**，不改判定、不改模型看到的正文 —— 补上 ⑥ 那条"从哪跳过来的看不见"。
> ⚠️ **这是我提的补法**（不是抄的）：把"静默"变成"可查"，成本约 5 行。

⇒ 这条进甲类施工清单，与 ⑥ 一起验收（独立 commit、先红后绿）。
