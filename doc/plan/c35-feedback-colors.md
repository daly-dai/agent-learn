## 一、需求（要做什么）

用户原话（2026-09-16，做 C8 T6 时）：**「方向键上下选中没有了」**。

查下来**方向键逻辑是好的** —— `ArrowDown` / `ArrowUp` 都在正常移 `commandActiveIndex`；坏的是**值**：`.active` 与 `:hover` 用的是**同一个** `var(--paper)`，而 `--paper` 与面板底 `--plate` 都是纯白 ⇒ **高亮画在等高的白上，等于不存在**。

⚠️ 这是**既有**缺陷，**不是 T6 引入的**（T6 只做了面板分组 / 模糊匹配那一批）。

**要做的**：让「悬停 / 键盘高亮」这类**反馈**在任何浮层里都看得见，并留下一条**能防止它再犯**的判据。（后半句来自池子行的验收 ③ 与下面第五条乙案）

## 二、根因

`app/globals.css:35-36`：`--plate: #ffffff`（浮层 / 卡片 / 顶栏）与 `--paper: #ffffff`（阅读面）**同值**。而多个组件写的是「**在 `--plate` 面上、拿 `--paper` 当 hover / 高亮**」⇒ **白底上的白底，反馈静默消失**。

**它是什么时候变成同值的（2026-09-18 用 git 核实，修正池子行里"2026-08-26 中性壳之后"这个说法）**：

| 时间 | 改动 | `--plate` / `--paper` | 反馈还看得见吗 |
|---|---|---|---|
| 2026-08-26 定 / 08-27 落（`7830df0`） | **第三次**：纸感退役、走中性壳（`doc/plan/ui-design.md` 的「V2 补记：纸感退役，走中性壳」那一节） | `#ffffff` / `#f8f8f8` | 勉强 —— 只差一档 |
| **2026-09-16**（`1eefc1c`，`git log -S"--paper: #ffffff"` 唯一命中） | **第四 + 第五次**（同一个 commit：白+黑，再修"边框太重"） | **`#ffffff` / `#ffffff`** | **彻底没有** —— 两个 token 同值 |

⇒ 真正的"归零"是 **2026-09-16 第四次调整**；用户**同一天**报障（C8 T6），所以它看着像"新 bug"，其实是同一次大改动带出来的既有缺陷。
⚠️ **`doc/plan/ui-design.md` 的 token 表还停在 `--paper #f8f8f8`**（表面色那行 + 那份「中性壳」补记）—— **缺第四 / 第五次调整的补记**，与本项相邻但不在本项范围。

## 四、影响面（⚠️ 范围未知，不是「只有这两处」）

`grep 'background: var(--paper)'` 全库约 **20 处**（2026-09-18 复核：**23 处命中，其中 1 处是注释**），落在 `--plate` 面上的都在内 —— ⚠️ **没有逐个核过**。

### 六.3 改动（与原型的差异，逐条说明为什么）

⚠️ **原型没有 `:hover` 规则**（它是布局原型，`grep ':hover'` 零命中）⇒ 这一项**没有反馈色的原型可改**；下面"改动"改的是**代码现状**，不是原型。

| 改动 | 为什么 |
|---|---|
| 新增 **2 个语义 token**：`--feed-hover` / `--feed-active` | 「反馈」是一类语义，不是一个深浅值。有了它，判据才写得出来（六.5），硬编码才收得回来 |
| 9 处状态底色从 `var(--paper\|--plate)` → `var(--feed-*)` | 反馈不再借「面」的 token ⇒ 以后再改面值，反馈不会跟着一起归零（**这才是根因**） |
| 统一**方向**：侧栏 hover 从"变亮"改成"变暗" | 同一个"悬停"在三个面上现在有两个相反方向（9/10 变亮 vs 11 变暗）|
| **5 处**硬编码 rgba 收编成 token（`command-menu` 的 `.03`/`.07`、`message-row .compactionHead:hover` 的 `.03`、`skill-card .head:hover` 的 `.03`、`repos .repoItem:hover` 的 `.06`） | 一个事实只写一处；同时让 09-16 已验收的那一对值成为**全站口径** |
| `ui-design.md` 的 token 表补第四 / 第五次调整 | 修掉六.0 那条"文档说 f8f8f8、代码是 ffffff"的不一致（否则下一个人还会按旧文档判断） |

**明确不动**：`.apparatusHead` 的 `rgba(29,33,39,.025)`（它是**卡片的头，是面**，不是反馈）、第 13 行的 `.is-current`（合法的面 + 边）、`--recorder` 改名（本文件第八节已划界）。

### 六.4 关键约束（设计里唯一"必须"的一条）

**JS 驱动的键盘选中不能靠 `:focus-visible` 的 outline 兜底。**

用户报障的那一处是**方向键移动 `commandActiveIndex`**（JS 改类名 `[data-active]`），**不走 DOM 焦点** ⇒ 全局那条 `outline: 2px solid var(--pen-user)` 根本不会画。所以：

- **键盘当前项必须自带可见背景**：`--feed-active`（比 hover 明确一档），**不许**只靠"它同时也是 DOM 焦点"来假设可见
- `--feed-active` 与 `--feed-hover` 的差必须**肉眼可辨**（`command-menu` 的注释原话：「高亮项：**比 hover 更明确** —— 用户要能分辨'焦点在哪一项'」，09-16 已按这条验收过）

### 六.5 落点与判据

**token 定义**（落 `app/globals.css`，值取 09-16 用户已验收的那一对）：

```css
/* 反馈（悬停 / 键盘当前项）：只用墨的透明档，不用色相 —— 色相留给五支笔。
   ⚠️ 反馈**不许**复用「面」的 token（--plate/--paper/--recorder）：面一改值，
   反馈就会静默归零（2026-09-16 就是这么发生的：两个面收成同一个 #ffffff）。 */
--feed-hover: rgba(29, 33, 39, 0.03);  /* 可点性：幽灵按钮 / 行 / 菜单项 */
--feed-active: rgba(29, 33, 39, 0.07); /* 键盘当前项（JS 驱动的选中） */
```

**改哪 9 处**：六.0 表里 1–12（13 不动）。**收编哪 5 处硬编码**：见六.3。

**判据（可脚本化，对齐 C28「会漂的东西改成跑一下就报」）**：新脚本 `scripts/check-feedback-tokens.mjs`
—— 扫 `app/**/*.css`，凡**选择器里带状态**（`:hover/:focus/:active/[data-*]/.is-current`）的规则，其 `background` **不许**出现 `var(--plate|--paper|--recorder)`；反馈档只许 `var(--feed-*)` 或结构编码（`box-shadow` / `border` / `outline`）。

### 六.6 待拍板（三点，都需要你点头）

1. **token 命名**：`--feed-hover` / `--feed-active`（我推荐，因为它直接说出"这是反馈"）/ `--wash-*`（更描述颜色）/ 别的
2. **侧栏 hover 方向反转**（变亮 → 变暗）：这是**看得见的行为变化**，要你真机看一眼再说行不行
3. **`repos .repoItem:hover` 从 .06 并到 `--feed-hover`(.03) 会不会偏弱**：那一行是大块面，.03 可能不够；若不够，是"给它单独一档"还是"把 `--feed-hover` 提到 .04"
