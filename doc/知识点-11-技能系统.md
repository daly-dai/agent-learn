# 给 agent 装技能系统：探索与抉择

一份技能正文动辄几千字。给 agent 装二十几个，全塞进提示词就是六万多 token —— 每问一句话都要付一次。

「技能系统」解决的就是这件事：**清单常驻、正文按需**。做法本身不复杂，**难的是落地时的抉择和取舍**。

---

## 一、skill 是什么

**技能（skill）= 一个目录 + 一份 `SKILL.md`。** agent 遇到匹配的任务时，按需把正文读进上下文。目录里还能放脚本和参考文件。

`SKILL.md` 开头是一段 YAML frontmatter。**必填两个键**：`name` 和 `description` —— 后者是模型判断"这活该不该用这个技能"的唯一依据。**可选键里我只认一个**：`disable-model-invocation`。其余（`user-invocable`、`whenToUse`、`metadata`、`argument-hint`、`license`）**一律不读，也不报错** —— 读了对行为没有任何影响。

一次真实动作长这样：

- 「帮我审一下这段代码」→ 模型自己判断该用 `code-review` → 它调一次 `skill` 工具 → 正文进上下文 → 它按那份清单审。
- 第二条路：输入 `/code-review` → **这一轮模型零工具调用**，宿主直接把正文塞了进去。

我的电脑装了 **29** 个技能（2026-09-15 实测），但**不是全部都会进模型清单**：写了 `disable-model-invocation: true` 的那 9 个会被摘出去 —— `retro` / `teach` / `writing-shape` / `handoff` 这类**要用户主动发起的流程**，让模型自己决定"要不要教你"是荒谬的。它们不在模型清单里，但 `/` 面板和 `/名字` 都到得了。

这份清单有多大：

|                                           | 字符数      | ≈ token |
| ----------------------------------------- | ----------- | ------- |
| 只放清单（同样这 29 个，只算名字 + 描述） | 4,736       | 2.4k    |
| 正文全塞（29 个技能的正文）               | 130,836     | 65k     |
| **倍数**                                  | **27.6 倍** |         |

## 二、终点：skill 长什么样

三个真实片段。

### 片段一 · 会话里存了什么，什么没存

会话是**一行一条消息**的日志。技能相关的东西分两类落进去。

**模型自己调 `skill` 工具** → 正文变成一条**工具结果**消息：

```json
{
  "role": "toolResult",
  "toolName": "skill",
  "content": [
    /* 那个信封，形状见片段三 */
  ],
  "isError": false
}
```

**用户打 `/名字`** → 宿主**追一条用户消息**（模型这一轮零工具调用）：

```json
{
  "role": "user",
  "content": [
    {
      "type": "text",
      "text": "用户用 /code-review 主动加载了这个技能，正文见下 —— 已经加载好了，不要再调 skill 工具加载它。\n\n/* 信封 */"
    }
  ],
  "source": { "kind": "skill-invocation", "name": "code-review" }
}
```

那个 `source` 标记干三件事：

1. 带标记的注入件**不会被再扫一遍** —— 否则它里面的 `/code-review` 每轮都触发一次注入，无限套娃；
2. 轨迹和界面上能分辨「**这段是宿主塞的，不是人打的**」；
3. 最终推给前端的是全量历史 ⇒ 注入件**留得住**，不用为它单独造一种消息类型。

⚠️ **而清单不落盘。** 它每次请求现拼进系统提示词（为什么这么选，见决定 ②）。

**待完善**：正文落进会话 ⇒ 它会**进轨迹、进压缩、进 token 统计、压缩吃掉技能正文**。

### 片段二 · 系统提示词里的「技能」那一节

系统提示词是按节拼出来的，技能清单是其中一节：

```markdown
你是 ……，一个可以独立完成任务的通用 AI agent。
你运行在一个安全工作区内，只能通过工具与文件交互。

## 当前日期

今天是：2026年9月17日星期四（时区 Asia/Shanghai）。
涉及「今年 / 最近 / 最新」这类相对时间时，一律以上面这个日期为准。

## 工具使用原则

- （只留不点名任何工具的通用规矩）
- `工具名`：该工具自己投稿的规矩

## 技能

以下技能可用。开始一项明确匹配某个技能的任务之前，先用 `skill` 工具加载它——不要凭名字猜内容。

- `code-review`: 对一段改动做双轴评审……
- `docx`: 创建、读取、编辑 Word 文档……
  …（21 条，合计 4,390 字符）

⚠️ 另有 N 个技能没有加载成功（原因如下）。如果用户问起……把下面这条告诉他：

- `某个技能`（/路径）：frontmatter 缺少 description —— 跳过这个技能
  …（这一份封顶 5 条）

## 什么时候必须联网

## 引用来源

## 输出要求
```

**为什么非得常驻给模型看？** 这是这一节最容易被跳过的一问。

因为「**模型不知道自己不知道**」。你完全可以不给清单，给它一个"列出有哪些技能"的工具 —— 但它得先**想到**去列，而它压根不知道有技能这回事，所以**不会去列**。

代价：清单是**每请求都付**的（2.4k token）。这个代价的天花板，就是第九个决定。

三个实现细节：

- **清单是"传进来的参数"**，这一层**不读文件** —— 固定字符串进、固定字符串出，好测；而且"技能根在哪"由调用方决定，将来它按工作区变的时候，这里一行都不用动。
- **空清单 ⇒ 整节省略**，绝不留下一个空标题 —— 空标题会让模型以为"**有技能但没列出来**"，然后去猜名字。
- ⚠️ **但"只有诊断、没有清单"不能省略** —— 那是"你装的技能全坏了"，恰恰最该说出来。

### 片段三 · skill 正文进上下文的样子

两条加载路径**共用同一份渲染**，所以模型无论被谁加载，看到的永远是同一个形状：

```xml
<skill_content name="code-review">
<skill_resources>
技能目录（绝对路径）：/Users/you/.agents/skills/code-review
正文里提到的相对路径都相对这个目录解析；要用到的脚本 / 参考文件按需再取（脚本用命令跑——会弹审批）。
目录下的文件：
- references/checklist.md
- scripts/hitl-loop.sh
</skill_resources>

<skill_instructions>
（SKILL.md 去掉头部之后的正文）
</skill_instructions>
</skill_content>
```

**为什么是信封，不是把 `SKILL.md` 直接贴进来？** 四条理由，从硬到软：

1. **正文没有边界。** 直接贴，模型不知道这段到哪儿结束 —— 后面紧跟着的是别的内容（同一条消息里的其他块，或者下一条消息）。没有明确的收尾，它可能被"接续"着往下读。信封给了明确的开始和结束。
2. **要说的话不止一段。** 除了正文，还得说：技能目录在哪、相对路径相对谁解析、目录里有哪些文件、脚本要跑会弹审批。这几样性质完全不同，裸贴会糊成一坨。
3. **资源和正文必须分开。** 资源清单是「**材料**」（给你查的），正文是「**指令**」（要你照做的）。
4. **两条路必须同形状。** 模型自己调工具、和用户点名注入，是两条完全不同的触发路径 —— 给出两种形状，模型得学两遍，我在轨迹和界面里也没法用同一个办法识别它们。

⚠️ **一个真实的缺口**：**正文字段不转义**（技能是本地可信内容），所以技能作者写的正文里如果出现 `</skill_instructions>`，**能提前把信封闭合掉**。我接受这个风险的依据是"技能是我自己装的" —— **这和「加载要不要弹框」那条用的是同一个前提**；一旦技能来源变成"别人分发的包"，这个假设会**同时塌两处**。
（名字倒是走了转义 —— 因为身份取目录名、不做校验，引号和 `&` 都可能出现。目录路径没转义：路径里出现 `<` 或 `&` 的概率极低，我认了。）

### 组装的注意点

这几条是拼装时最容易栽的（括号里标了属于哪一片段）：

- **清单顺序必须可复现。** 同一批技能，永远生成同一份提示词 —— 否则前缀缓存**每请求都失效**（跟决定 ② 是同一个坑）。所以排序**不能用跟地区设置相关的比较**。（片段二）
- **技能根每请求只扫一遍。** 清单、手势注入、命令面板三处**共用同一份扫描结果**，不为了三个地方各扫一次。（片段一 / 二）

## 三、让它跑起来（5 个决定）

从"agent 手上什么都没有"，到"模型能自己加载、用户也能点名加载"。**这五环是一环扣一环的。**

### ① 新增一个专门的动作，还是让 agent 自己去读文件？

**面临的问题** 不解决就得默认走"复用读文件能力"这条路 —— 而它在我这儿**物理上不工作**：技能装在**工作区之外**的目录里，而读文件的工具被**围栏**关在工作区内。模型不是"不太会读"，是**根本读不到**。

**参考** 公开的 Agent Skills 标准里写着：专用工具是给"宿主**没有**文件读取能力"留的那条路。pi 走的是另一条 —— **不新增工具**，清单里给出绝对路径，让模型用自己的读文件能力去读。⚠️ 而它**自己承认模型常常不读**（三次都只是补文档，**没有改机制**）。DSH 则用了专用工具，参数只有一个技能名。

**选择**：新增专用工具。我的agent和 pi 一样有读文件能力，本来可以走它那条路。

**⚠️ 隐患。** 两个**可观测的触发点**：

1. **模型不去调。** 工具路线**也不保证模型会调**，它只保证"调用的时候能拿到结构化的东西"。触发点 = 轨迹里出现「**模型声称用了某技能、却没有对应的工具调用**」。
2. **一次给全文 vs 可以只读一部分。** 工具路线把正文**整篇**塞进上下文；读文件路线模型能自己只读前 N 行。触发点 = **最大技能正文字符数**（今天 10,733，还能接受）。

**→ 下一个问题**：有了这个动作，它怎么知道**有哪些**技能可加载？

---

### ② 那张技能清单放在哪：每次都现拼，还是写成一条真消息？

**面临的问题** 清单只能待在两个地方之一 —— **每次请求现拼的系统提示词**，或者**写进会话历史的一条消息**。放错地方的具体后果：技能集合一变，历史里那条清单就**过期**，模型手里同时有**两份**；而且旧那份还会被落盘、进轨迹、进压缩、进 token 统计。

**参考** pi 放系统提示词。DSH 放**持久消息 + 按条目差异追加替换**。
而 DSH 那套"差异替换"**是被它自己的前提逼出来的** —— 它的会话是"日志 + 投影"架构（凡是模型看到的都要能从日志重放），系统提示词不算日志的一部分，所以清单只能做成消息，于是**必须**解决"历史里那张旧清单怎么办"。

**选择**：系统提示词、每请求现拼、不落盘。
代价明说：系统提示词一变，**前缀缓存就失效**。而这个代价**本来就在付**。反过来走 DSH 那条，要新做三件事（发布 / 差异比较 / 替换）—— **那三件事解决的是我没有的问题。**

**→ 下一个问题**：清单里每条技能都得有个名字。**这个名字谁说了算？**

---

### ③ 技能的身份，取目录名还是取文件里写的名字？

**面临的问题** 取文件里写的名字，就**必须发明一套同名裁决规则** —— 谁赢？报错还是覆盖？跨来源谁优先？而这套规则**永远有人不满意**。

**参考** 四家四种：

|            | 身份取什么                   | 名字规则                         | 重名怎么办                 |
| ---------- | ---------------------------- | -------------------------------- | -------------------------- |
| **本项目** | **目录名**                   | 不校验                           | **造不出来**（零裁决代码） |
| pi         | 文件里的名字，缺了退回目录名 | 硬校验：长度、字符集、连字符位置 | 收集成一张冲突列表报出来   |
| DSH        | 注册名                       | 正则校验，不合格**直接抛错**     | **四层优先级** + 警告      |
| opencode   | 文件里的名字，缺了退回文件名 | 不校验，没名字就跳过             | **后者静默覆盖前者**       |

**选择**：目录名。
但正确的说法**不是**"我解决了重名问题"，而是「**重名在我这儿造不出来**」—— 同一层目录下目录名天然唯一，于是别人那整套优先级机制在我这儿**根本不需要存在**。

**这是结构优势，不是功能优势** —— 差别很重要：功能优势会被新需求推翻，结构优势不会。

**⚠️ 隐患。** 不校验名字，名字里就可能出现引号和 `&`，而包住正文的那对标签**必须转义**。
另外 —— **一旦将来要扫第二个技能根，这条优势就打折**（跨根就又有同名了）。

**→ 下一个问题**：模型现在能自己加载了。可**用户想点名**呢？

---

### ④ 用户主动点名和模型自己判断，两条路怎么不打架？

**面临的问题** 用户在输入框里打了 `/code-review`，如果这还只是"给模型一个提示"，那**他明确要求了还要赌模型会不会去读** —— 而模型判断失误时，**用户没有任何补救手段。**

**参考** DSH 两条路径**共用同一份渲染**，并明写了防重复加载；它的可见性是**两个开关**（`disable-model-invocation` 挡"模型不可调"，`user-invocable` 只挡"用户不可调"）。

**选择**：手势那条 = **宿主扫消息 → 直接追加一条用户消息 → 这一轮模型零工具调用**；两条路径**共用同一份渲染**。
两条路在轨迹里也分得开：**一眼看得出这段是宿主塞的，不是用户手打的。**
我只有一个开关，所以形状是：**工具路径尊重它、手势路径放行** —— 对应"作者禁止模型自己喊，但没禁止用户点名"。

**⚠️ 隐患。** 名字后面**紧跟中文标点**（`/code-review，`）不命中 —— 边界就是空白。从面板走踩不到（面板插入的是带尾空格的形式），**手打不加空格会静默失效。**

**→ 下一个问题**：用户打出来的那个名字，我怎么认出它是技能名、而不是一个路径？

---

### ⑤ 怎么判断"这段文字里提到了某个技能名"？

**面临的问题** 用正则认，就得先**规定名字长什么样**。一旦规定了，不符合的名字（**中文名**、带点、带大写）会被**静默忽略** —— 而这跟 ③ 刚定的"身份 = 目录名、不做名字校验"**直接打架**。

**参考** DSH 用的是一条严格的小写连字符正则。照搬过来，**中文技能名永远静默失效。**

**选择**：拿到那个词之后，**去技能名单里精确查**（跟身份用同一把尺），查不中就当普通文本。
这一条顺带免掉了两类误判：`5/8`、`/usr/bin` **天然查不中**，不需要为它们写特例正则。

**⚠️ 隐患。** 技能名里**带空格**的时候 —— 边界是空白，那一半永远点不到。（这是取舍，不是 bug）

**主链路到此通了**：模型能自己加载，用户也能点名加载。

## 四、让它不出事

链路通了，接下来看稳不稳。三个保障。

### ⑥ 遇到一个写坏的技能，整体报错还是跳过？

**面临的问题** 技能文件是**用户手写的**，随时可能写坏。直接报错 ⇒ **agent 起不来**（而我只是想加个技能）；静默跳过 ⇒ **我以为它在，其实没加载。**

**参考** codex 把每个技能根的错误**单独收集**；pi 生成警告但**尽量照常加载**；DSH 专门做了一个**诊断概念**。三家都不选"整体失败"。

**选择**：跳过坏的、其余照常，但**诊断必须可见** —— 而且是**三层可见**：服务端日志 / 接口响应 / **系统提示词里那段交代**。

第三条是抄 Reasonix 的：我看过的几家里**只有它做到"零界面成本还真的到得了人"** —— 办法是**把话写给模型，让模型转告用户**。

另外：给模型看的那一份**封顶 5 条**，超了**必须如实报数**（"还有 N 个没列出"）。**封的是展示，不是事实** —— 日志和接口照给全量。

**⚠️ 隐患。** **已经知道会** —— 这条通道**依赖模型配合**，模型不提，用户还是不知道。我**自己把它标成"弱可见"**。
可观测的触发点：**用户问「我装的 X 怎么没生效」** —— 那一刻就是它失效了，该去补一个能主动查的清单。

---

### ⑦ 加载技能要不要弹框批准？

**面临的问题** 弹框 ⇒ **每一次只读动作都打断我**；不弹 ⇒ **放行了一条读工作区之外文件的通道。**

**参考** 我自己的先例是"不在需要确认的清单里就自动放行"（读文件、抓网页都走这条）。**opencode 反过来 —— 它的技能加载要过权限**，可以被拒绝，也可以记住选择。

**选择**：自动放行。理由三条：

1. 技能是**我自己装的**，不是模型写进去的；
2. **自动放行不等于脚本会自动跑** —— 加载只读一个文本文件，脚本要跑必须再调一次命令执行，而**那条路必弹框**；
3. 我的电脑上 10 个技能脚本**今天干净**（只引用了标准库和文档库；无网络、无子进程、无删目录）。

⚠️ 但**"今天干净"不是安全边界** —— 技能来自公共仓库，拉一个新技能就可能不干净。**边界是命令执行那一次弹框。**

**⚠️ 隐患。** **技能根不再是"用户自己装的"** 的时候 —— 一旦支持项目级技能、或别人分发的技能包，"用户自己装的"这个前提就没了，那时走权限才是对的。
另外我还**查出一个口子并认下不修**：读文件 + 抓网页**双自动放行** ⇒ 一个坏技能可以指挥模型「读工作区里的文件 → 发到外部地址」。缓解事实是密钥文件在工作区**外**，读不到 ⇒ **可外发的范围被限制在工作区内。**

### ⑧ 技能自带的脚本和参考文件，怎么让模型知道？

**面临的问题** 正文里写着"运行 `scripts/foo.sh`"，而模型**不知道那个文件在不在**、也不知道**相对谁**解析 —— 只能猜路径。

**参考** opencode 的做法：上限 **10 个文件**，列之前先把技能文件自己剔掉，排序后截断；而且它**明确告诉模型这份清单是抽样**；只在技能文件真的叫 `SKILL.md` 时才列。

**选择**：正文 + **技能目录的绝对路径** + 文件清单（同样封 10 个）+ 一句"相对路径相对这个目录解析"；脚本一律**用命令执行去读或跑，每次弹框**（这个摩擦先认下，不优化）。
一处我比它好：它写"这是抽样的"，我写的是「**共 N 个，这里只列前 10 个**」—— **给了总数。**
另外我往工具描述里写了两条红线：**依赖缺失要如实报告**、**不要自己去装包。** 第二条是必需的 —— 我的电脑没装文档处理库，技能脚本一跑必报找不到模块，而模型的下一个动作**几乎必然是去装包**，往全局 Python 环境里写东西。

**⚠️ 隐患。** 文件超过 10 个时 —— 模型想跑的那个**可能不在清单里**。（已经付了，且有明文降级提示）

### ⑨ 可见技能上百怎么办

**面临的问题** 清单是**每请求都付**的钱。21 条可见（2026-09-16 复测）= **4,390 字符**（约 2.4k token）；到 100 条就是**两万字符，每问一句付一次。**

**参考** **没有一家解决。** pi 完全不封；DSH 封的是"**每条**不超过 500 字符"，而我**最长的才 434** ⇒ **对我等于没生效。**

**选择**：先不解决，立了项。

**⚠️ 隐患。** 可观测判据就是**清单体积** —— 去量你自己的字符数。

⚠️ 我提议直接照抄 Reasonix 的 **4000 字符**上限 —— 实测**我今天就 4,390**，照抄 = **今天就把在用的技能砍掉** = 制造静默失效。

> **「有答案」≠「答案是给我的」。**

要定这件事，得先回答三个问题，而我一个都还没回答：

1. 上限按**什么维度**的量 —— 条数 / 字符 / token？（几家口径**互不可比**：DSH 是"每条 ≤500 字符"，我这边是"总量 4,390 字符 / 21 条"，**主体都不一样**）
2. 超了**砍谁** —— 按字母序不公平；按重要性我没有重要性字段；让用户自己标，就得给 `SKILL.md` 的头部加键，而它的头部刚定为**只认 3 个键**。
3. **真机数据** —— 今天 21 条，**还没到痛的时候。**

## 六、回头看：这些决定留下的坑

- **坏技能可能静默吞正文。** 我曾经把正文里的分隔线当成了头部信息的收尾 → **前半段正文被吞掉，而技能照常加载、零诊断。** 残余边界至今修不完。
- **压缩会吃掉技能正文。** 正文以工具结果进上下文，而压缩时摘要**只看到它的前 2,000 字符**，技能正文却多在 3,000–10,700 ⇒ **压缩一次，技能就失效了。**
  **我决定不修** —— 因为压缩阈值约 98 万 token，真机从没遇到过；只记了触发条件。
